Elliptic Curves vs the Caesar Cipher: Encryption, Statistical Cryptanalysis and Small Key Spaces

21/10/2026

Part 1 — Encrypting with the toy elliptic-curve scheme

In Homework 1 the private key $k$ gave the public key $Q = kG$. Here the same pair is used to encrypt with the EC-ElGamal scheme on the real curve secp256k1, $y^2 = x^3 + 7 \pmod p$ with $p \approx 2^{256}$ and a base point $G$ of prime order $n$. The only toy feature is the private key, drawn from $1 \le k \le 2^{b}$ with $b = 20$ instead of $1 \le k < n$.

  1. Key generation (receiver). Choose the private key $k$ at random and publish $Q = kG$.
  2. Encoding. ElGamal encrypts points, not text: each 30-byte block $m$ of the message becomes a point $M = (x, y)$ with $x = 256\,m + j$, for the first $j$ that puts $x$ on the curve (Koblitz's method).
  3. Encryption (sender). For every block, choose a fresh random ephemeral key $r$ and send
    $$C_1 = rG, \qquad C_2 = M + rQ$$
  4. Decryption (receiver). Compute the shared point and subtract it:
    $$S = kC_1 = k(rG) = r(kG) = rQ, \qquad M = C_2 - S$$
    then read $m = \lfloor x / 256 \rfloor$ and turn it back into bytes.

Part 2 — The Caesar cipher

Number the letters $a = 0, \dots, z = 25$. The key is a shift $s \in \{0, \dots, 25\}$ and every letter is moved by the same amount:

$$c = (p + s) \bmod 26, \qquad p = (c - s) \bmod 26$$

It is a symmetric cipher: the same secret key encrypts and decrypts. Spaces and punctuation are left unchanged. The message is the same as in Part 1.

Comparing the two schemes

The two ciphers are more alike than they seem: both add a secret mask in a group and subtract it to decrypt. Caesar adds the number $s$ in $\mathbb{Z}_{26}$; EC-ElGamal adds the point $rQ$ on the curve. The difference is that Caesar adds the same mask to every letter, while EC-ElGamal adds a new, unpredictable mask to every block, and only the owner of $k$ can rebuild it.

Statistical properties of the ciphertext

The same 600-letter passage of English, encrypted with both schemes:

Caesar is a permutation of the alphabet, so the letter histogram keeps its exact shape: the peaks of E, T, A, O are still there, only under different letters. The EC-ElGamal ciphertext is a pair of essentially random curve points, and its digits are flat around 1/16: the plaintext statistics do not survive encryption.

Statistical cryptanalysis of the Caesar cipher

The corpus. The model of English is learned from a reference corpus, the opening chapters of Pride and Prejudice (Jane Austen, 1813, public domain from Project Gutenberg). Test messages come from a different book, The Adventures of Sherlock Holmes (Arthur Conan Doyle, 1892), so the attack is never tested on the text it learned from.

The algorithm

With only 26 keys, the attacker tries every key and keeps the decryption that is most likely under the model learned from the corpus. Three ways to score it:

  • Exhaustive search + dictionary. Decrypt with all 26 keys and keep the one whose words are most often among the 300 most common words of the corpus.
  • Chi-squared (letter frequencies). For each key $s$, compare the letter counts $O_i(s)$ of the decryption with the counts expected from the corpus frequencies $p_i$, for a text of $N$ letters, and keep the key with the smallest distance:
    $$\chi^2(s) = \sum_{i=0}^{25} \frac{\left(O_i(s) - N p_i\right)^2}{N p_i}$$
  • Bigram scoring (n-grams with n = 2). Use the probability of each letter given the previous one, estimated from the corpus with a word-boundary symbol and add-one smoothing, and keep the key with the highest log-likelihood:
    $$\ell(s) = \sum_{i} \log P\left(t_i \mid t_{i-1}\right), \qquad t = \text{decryption with key } s$$
    Pairs such as "th", "he", "in" are common, "qz" or "xj" almost never occur, so this score uses the order of the letters and not only their counts.

How much ciphertext is needed?

For each length, 500 random passages of the test book are encrypted with a random key from 1 to 25, and each method tries to recover it. The curve is the share of keys recovered exactly.

Effectiveness and limitations

  • Long ciphertexts are always broken. From about 50 letters the chi-squared and bigram attacks recover the key every time: the observed frequencies converge to the true ones (law of large numbers).
  • Short ciphertexts are the hard case. With 5–10 letters the sample is too small to estimate 26 frequencies and chi-squared often fails. Bigrams do much better, because they also use which letters follow each other.
  • The model must match the text. The attack assumes English: a text in another language or with unusual frequencies can point to a wrong key, and a very short message can have several equally plausible decryptions.

Attacking the toy scheme: the restricted key space

The EC-ElGamal ciphertext gives no statistics to exploit, but the toy private key satisfies $1 \le k \le 2^{b}$. The attacker only needs the public key: find $k$ such that $kG = Q$, then decrypt exactly like the receiver, $M = C_2 - kC_1$. Two algorithms:

  • Brute force. Compute $G, 2G, 3G, \dots$ with one point addition each and compare with $Q$. On average $2^{b-1}$ additions, with no memory.
  • Baby-step giant-step (BSGS). Write $k = im + j$ with $m = \lceil \sqrt{2^{b}} \rceil$. Store the baby steps $jG$ for $0 \le j < m$ in a table, then take giant steps $Q - i(mG)$ for $i = 0, 1, \dots$ until one is in the table: then $Q - imG = jG$, so $k = im + j$. About $2\sqrt{2^{b}} = 2^{b/2 + 1}$ additions, but $2^{b/2}$ points of memory.

Why this would not work on real ECC

Both algorithms are generic: their cost grows with the size of the key space, $2^{b}$ for brute force and $2^{b/2}$ for BSGS. On a properly configured secp256k1 the private key is uniform in $1 \le k < n \approx 2^{256}$: brute force needs about $2^{255}$ additions, and the best known attack, Pollard's rho, still about $2^{128}$, far out of reach. The toy is broken not because the curve is weak, but because $b$ is small.

Conclusion

Both schemes encrypt by adding a secret mask in a group, but they fail in opposite ways:

  • Caesar is broken by statistics. It maps each letter to one fixed letter, so the frequencies of English pass straight into the ciphertext. With a corpus to learn them, chi-squared recovers the key from a few dozen letters, and bigram scoring from fewer than ten. Its 26 keys make it worse, but they are not the main problem: a cipher with $2^{88}$ keys built in the same way falls to the same analysis.
  • The toy EC scheme is broken by its key space. Its ciphertext is randomized and statistically flat, so frequency analysis has nothing to work on. But with $k \le 2^{20}$ brute force finds the key in seconds, and baby-step giant-step in a fraction of a second, using only the public key.
  • Real ECC removes the shortcut. With a private key uniform in $[1, n)$, $n \approx 2^{256}$, the best generic attacks need about $2^{128}$ operations, which is out of reach. What remains to get right is the design: fresh random ephemeral keys, point validation and authenticated encryption, as in ECIES.

A good cipher needs both properties at once: a ciphertext with no visible statistics, and a key space too large to search.
